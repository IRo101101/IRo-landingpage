# Recreate this site as a single HTML file: NORTHWALL

You are an expert creative front-end developer. Produce a **single self-contained `index.html`**
that reproduces the project below **exactly** — same layout, copy, visuals, motion and interaction.
Pure HTML/CSS/JS in one file: no build step, no framework, no bundler. ES modules inline in a
`<script type="module">`. **Lenis is the only external code**, pulled through an import map; there
is no three.js and no canvas on this page. The spring solver, the shared ticker, the in-view
observer, the word-by-word text engine, the loading panel, the counting figures, the rolling
labels and every hover are all written by hand. Hardcode every value given here as a fixed
constant.

Every number below is the shipped default, measured off the 1440×800 design frame. Nothing in
this document is a suggestion.

## What it is

A one-page site for **Northwall Construction**, a construction firm ("Building spaces that last.",
"Built for today. / Created for generations.", "123 Madison ave., new york, 10016, usa"). Six
blocks alternating between **black** (`#000000`) and an **off-white** (`#f5f5f5`), set entirely in
**DM Sans**, with architectural photography and a drafting-drawing vocabulary throughout: dashed
hairline rules, 4px square markers pinned to the corners of every box, uppercase 14px labels at
−0.03em tracking.

The page opens behind a black panel where a monogram fills white from the bottom like a gauge
while photo cards are dealt beneath it; the last card is the hero's photo, and it grows out of the
centre until it covers the hero exactly, the monogram flies into the header's logo slot, and the
panel fades over a hero that already looks identical to it. Only then does the hero's copy play in.

Scrolling is smoothed by Lenis. One fixed background layer serves the whole page and springs
between black and off-white as blocks pass the middle of the viewport, so the surface never cuts
at a section edge; the fixed header recolours itself on the same line. Every block's contents
drift down and fade as the block scrolls out. Almost everything moves on a spring — there are
essentially no CSS keyframes on this page.

## The animation engine (write this once, use it everywhere)

Every moving thing on this page is a critically-ish damped spring integrated on one shared ticker.
Implement this first — the sections below refer to its parts by name.

### 1. Spring solver

A spring is `{ tension, friction, clamp? }` integrated per frame at a fixed 1/60s step:

```js
const STEP = 1 / 60;
function advance(s, dt) {              // s = { value, velocity, target, tension, friction, clamp }
  let acc = Math.min(dt, 0.064);       // never integrate more than ~4 frames of catch-up
  while (acc > 0) {
    const h = Math.min(STEP, acc);
    const force = -s.tension * (s.value - s.target);
    const damp  = -s.friction * s.velocity;
    s.velocity += (force + damp) * h;
    s.value    += s.velocity * h;
    acc -= h;
  }
  if (s.clamp && ((s.velocity > 0 && s.value > s.target) || (s.velocity < 0 && s.value < s.target))) {
    s.value = s.target; s.velocity = 0;
  }
  if (Math.abs(s.value - s.target) < 0.0005 && Math.abs(s.velocity) < 0.0005) {
    s.value = s.target; s.velocity = 0; return true;   // at rest
  }
  return false;
}
```

A "spring group" animates several named channels at once (`{ opacity, y, scale, … }`) from a `from`
object to a `to` object, writes them to a element's style each frame, and reports when all channels
rest. Units: `y`/`x` given as a number are **px**; given as a string ending in `%` they are a
percentage of the element's own box (use `translate3d(x, y, 0)` with the `%` unit). `scale`,
`scaleX`, `scaleY`, `rotate` (deg), `rotateX`, `rotateY` (deg), `blur` (px, into
`filter: blur(Npx)`) and `clipPath` (interpolate the inset percentages) are all channels.
Compose transforms in this order: `translate3d(…) rotate(…) rotateX(…) rotateY(…) scale(…)`.

### 2. One ticker

A single `requestAnimationFrame` loop drives every live spring. Springs that have come to rest are
removed from it. Some consumers ask to be sampled at a lower rate — a `frameInterval` in ms, which
the loop honours by skipping frames for that consumer. Used below as: **scroll scrub 32ms (~30fps)**,
**the ground watcher 150ms**, **the header watcher 80ms**. These exist because each of those
callbacks does a `getBoundingClientRect` — a forced layout — and the travel is slow enough that
sampling faster buys nothing.

### 3. The four behaviours

- **`Inview(el, {from, to, config, delayIn, once})`** — an `IntersectionObserver` starts the spring
  the first time the element enters the viewport. `once` latches; otherwise it plays back out when
  the element leaves.
- **`Hover(el, trigger, {from, to, config})`** — the spring targets `to` while `trigger` is hovered
  (or focused) and returns to `from` on leave. **Disabled at ≤768px**, where there is no hover:
  those elements render in their `to` state outright (each section below says where this matters).
- **`Spring(el, {from, to, config})`** — a plain state-driven spring, retargeted whenever the state
  it reads changes.
- **`Scrub(el, {start, end, from, to, config, frameInterval})`** — scroll-linked. `start` and `end`
  are two-word pairs read as `<element edge> <viewport edge>` — `"top bottom"` means "the element's
  top reaches the viewport's bottom". Compute progress 0→1 between those two moments each sampled
  frame and set the spring's **target** to the interpolated value, so the spring still smooths the
  scroll rather than tracking it rigidly.

### 4. The word-by-word text engine

Several headings and every body paragraph animate word by word. Split the text on spaces and wrap
each word in a `<span>`; the words are **flex items** in a `display: flex; flex-wrap: wrap`
container (so set `column-gap: 0.266em` to carry the spaces — that is DM Sans's space advance and
anything else re-wraps the paragraph), each word clipped by an `overflow: hidden` wrapper so it can
rise out of nothing. Set `justify-content` from the alignment the section asks for. Two presets:

```js
// Display headings
const HEAD_IN  = { y: "0%",  opacity: 1, scale: 1   };
const HEAD_OUT = { y: "80%", opacity: 0, scale: 0.9 };
const HEAD_STAGGER = 55;                       // ms between words
const HEAD_CONFIG  = { tension: 180, friction: 26 };

// Body copy — every description on the page runs exactly this
const COPY_IN  = { y: "0%",  opacity: 1, scale: 1    };
const COPY_OUT = { y: "60%", opacity: 0, scale: 0.94 };
const COPY_STAGGER = 22;
const COPY_CONFIG  = { tension: 210, friction: 28 };
```

Give the container `line-height: 1.1` minimum so a clipped reveal is not cropped by the line box.
Mode `once` latches on first entry; mode `always` replays on re-entry.

Shared section-entry timing: **`ENTRY_DELAY = 180`ms** (the surface arrives first, the copy after
it), **`ENTRY_STAGGER = 110`ms** between successive items inside one section.

### 5. Reduced motion

`@media (prefers-reduced-motion: reduce)`: every spring lands immediately, the loading panel
resolves at once, the about gallery and the process steps hold a single frame instead of looping.

## The loading panel (this is the hero moment — build it precisely)

A fixed `inset: 0`, `z-index: 60` black panel over the whole page.

**The gauge.** A centred monogram — `mark-northwall.svg`, drawn twice as a CSS mask
(`-webkit-mask: url(…) center/contain no-repeat; background: currentColor`) so it takes the panel's
colour. The bottom copy is white at `opacity: 0.20` and always visible, so the shape reads from the
first frame; a white copy on top of it is clipped by
`clip-path: inset(${(1 - progress) * 100}% 0 0 0)` and fills from the bottom as progress rises.
The monogram box is `aspect-ratio: 52/32`, `width: 46vw; max-width: 22rem` (≥640px: `34vw`,
≥1024px: `26vw`).

**Progress.** It creeps toward **`HOLD_AT = 0.72`** while the page is still loading and only runs
the last stretch once `window.load` **and** `document.fonts.ready` have both resolved — with a
**`MAX_WAIT = 4000`ms** failsafe so a slow asset can never trap the site behind the panel. Two
configs: the creep is `{ tension: 60, friction: 30 }`, the closing run to 1 is
`{ tension: 150, friction: 30, clamp: true }` so the mark tops out instead of easing at it.

**The readout.** Bottom of the panel, `1.5rem` from the edge (≥1024px: `2rem`), `1rem` side gutter
(≥640px: `2rem`), uppercase 12px at `--tracking-nav` in `--on-inverse-muted`: the word `Loading`
on the left, and on the right the percentage, zero-padded to two digits —
`String(Math.round(progress * 100)).padStart(2, "0") + "%"`.

**The deck.** Beneath the mark, a centred slot sized
`13.25rem × 16.25rem` (≥768px `18rem × 22rem`, ≥1024px `20.625rem × 25rem`). Five photo cards are
dealt into it on a fixed beat independent of loading, so the sequence always reads as one:
**`CARD_LEAD = 180`ms** then one card every **`CARD_INTERVAL = 240`ms**. Each card springs in with
`{ opacity: 0→1, scale: 0.82→1, y: 48→0, rotate: tilt*1.8 → tilt }` on
`{ tension: 190, friction: 24 }` — it swings past its angle and settles on it. The cards, in order,
with their resting tilt in degrees:

| # | photo | tilt |
|---|---|---|
| 1 | `hero/project-1.webp` | −12 |
| 2 | `about/about-6.webp` | 9 |
| 3 | `hero/project-2.webp` | −5 |
| 4 | `about/about-9.webp` | 14 |
| 5 | `hero/project-3.webp` | −8 |

**The finale.** The sixth and last card is the hero's photo, `hero/project-4.webp`. It is dealt
square on top of the deck (`{ opacity: 0→1, scale: 0.82→1, y: 48→0 }`, same card config) and holds
there for **`FINALE_HOLD = 280`ms** once everything is in. Then, in one move:

1. **It grows onto the hero.** Its frame is animated as `left` / `top` / `width` / `height` in
   **viewport pixels** — not a transform, because `object-cover` has to re-crop the photo as it
   grows. It starts at the deck slot's own `getBoundingClientRect()` and targets the rect of
   `[data-hero-stage]` (the whole viewport if that element is missing). Config
   `{ tension: 80, friction: 16, clamp: true }` — it arrives at speed and stops dead at size.
2. **The monogram flies to the header.** The panel carries an invisible copy of the mark in the
   header's own slot (same row height and gutter), so the travel is measured against the real
   layout rather than guessed and lands correctly at any width: take both
   `getBoundingClientRect()`s and spring `x`, `y` to the centre-to-centre delta and `scale` to
   `to.width / from.width`, on `{ tension: 210, friction: 34, clamp: true }`. The readout's veil
   fades to 0 on the same spring. The mark stays where it lands — the header's own copy is exactly
   beneath it and takes over as the panel fades.
3. **Then the panel lifts.** When the frame rests, call `lenis.start()` first (the scrollbar
   returns and narrows the hero by its width), re-measure the stage on the next
   `requestAnimationFrame` and snap the photo to it, then fade the panel's opacity to 0 on
   `{ tension: 320, friction: 30, clamp: true }`. Remove it from the DOM on rest.

**The handoff.** As the panel's opacity crosses **`RELEASE_AT = 0.35`** on the way down, fire a
one-shot `handoff` signal. Every piece of the hero's copy is held invisible until that signal and
then plays its entrance — late enough that the first words rise in view rather than behind the
panel, early enough that there is no pause after the photo lands. The copy is in the document the
whole time (visible to crawlers and screen readers), just `visibility: hidden`.

**Both draw the photo identically** — this is what makes the handover seamless. The panel's last
card and the hero's backdrop use the same layer inside their frame:
`position: absolute; inset-inline: 0; bottom: 0; height: 130%` with the image `object-fit: cover`.
The layer is taller than the frame and bottom-aligned so the hero's parallax can sink it without
exposing the top edge.

**Media warm-up.** Only **after** `window.load`, in a `requestIdleCallback` (timeout 2000, falling
back to a 500ms `setTimeout`), prefetch the rest of the page's photos with a **3000ms** budget.
Never during load — the hero photo is the largest contentful paint and thirty below-the-fold images
racing it costs far more than the smooth first scroll it buys.

Without scripting the curtain would never lift, so add `<noscript><style>[data-preloader]{display:none}</style></noscript>`.

## The page ground and the section flow

**One background for the whole page.** A `position: fixed; inset: 0; z-index: -10` layer. Every
section declares `data-ground="dark"` or `"light"`; a watcher sampled every **150ms** finds the
section covering `window.innerHeight / 2` and springs the layer's `background-color` between
`#000000` and `#f5f5f5` on `{ tension: 90, friction: 26 }`. The blocks paint no ground of their own,
so the surface changes on its own clock while one block's contents leave and the next arrive — the
seam never appears.

**Every section's contents drift out.** Wrap each of the six sections in a scrub that runs
`start: "bottom bottom"` → `end: "bottom top"`, `from { y: 0, opacity: 1 }` → `to { y: 50, opacity: 0.25 }`,
config `{ tension: 110, friction: 26 }`, sampled at **32ms**. This moves content only — the ground
is a separate fixed layer and stays untouched.

## The fixed header

## The shared interaction primitives

Write these once — they are used on every button on the page.

**`RollLabel`** — the label lifts out of the top while a second copy rises into its place, both
clipped by the line box (`position: relative; overflow: hidden`, the second copy absolutely
positioned). On hover: first copy `y: 0% → -100%`, second `y: 100% → 0%`, both on
**`{ tension: 260, friction: 26 }`**.

**`SwapArrow`** — a `0.625rem` square box, `overflow: hidden`, holding two copies of
`about/icon-arrow-light.svg` (or `hero/icon-arrow.svg` on the dark header) drawn as masks so they
take the button's colour and rotated 90°. On hover the first leaves right (`x: 0 → 16`) and the
second arrives from the left (`x: -16 → 0`) on **`{ tension: 300, friction: 26 }`**. It reads as
the mark being handed on rather than nudged.

**`ArrowLink`** — a row whose label drifts `x: 0 → 4` on `{ tension: 300, friction: 26 }` while its
`SwapArrow` hands over.

**`RollLink`** — an anchor wrapping a `RollLabel`.

**Counting figures.** Any figure written as text — `"18 years "`, `"120+"`, `"2.4M m² "`,
`"15+ years "` — is split on its first number with `/-?\d+(?:[.,]\d+)?/` into prefix, value and
suffix. Only the number animates, counting from 0 to the value on
**`{ tension: 90, friction: 34 }`** when the figure first enters view (latched — it reads as an
arrival, not a loop), rendered to 1 decimal place if the source had one, else 0. The prefix, unit
and label never move, so the reading stays stable while only the digits tick.
